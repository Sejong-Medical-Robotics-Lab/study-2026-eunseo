# 학습일지 - 2026-08-05 (week 3)

## 오늘 배운 것
- URDF란 로봇의 물리적인 구조를 설명하는 파일이다.
- STL mesh는 로봇 부품의 3차원 형상 데이터를 저장하는 파일이고 그리퍼 xacro는 그리퍼를 어떻게 연결하고 움직일지 정의한 파일이다.
- grasp_tcp(tool center point)는 가상의 기준 좌표계이다. 로봇으로 물체를 잡을때 관심있는 지점은 Link7중심이 아니라 두 손가락 사이의 실제 파지 위치이기 때문에 필요하다
- MoveIt은 로봇이 목표자세까지 어떻게 움직일지를 계산하는 것이다.(경로 계산)
- controller는 토픽을 통해 MoveIt이 계산 경로를 받아 실제 관절에 명령을 보내는 것이다.(ROS2안에서 동작하는 제어 프로그램)
- Gazebo는 물리 시뮬레이션으로 로봇의 joint가 실제로 시간에 따라 움직이고 controller와 연결된다.
- JointTrajectory는 각 관절이 언제 어떤 위치에 있어야하는지 정해놓은 시간표
- name 배열과 position 배열이 같은 순서로 짝지어진다.
- action은 목표 전송, 진행 피드백, 완료/실패 결과, 중간 취소가 가능한 통신 방식이다.

## 오늘 직접 해본 것/ 성공한 것
- URDF 변환 저장소에 EG2-4C2가 결합된 모델의 압축 파일에서 메시와 그리퍼 xacro만 뽑아서 그리퍼 모델 파일을 가져와 팔본체와 그리퍼 결합 URDF를 만들었다.
- RViz에서 로봇 모델을 확인하고 마커를 움직여 목표를 지정하고 plan과 execute을 실행하였다.
- RViz에서 scene 탭에서 박스 장애물을 추가 후 다시 plan했을 때 경로가 장애물을 피해 달라지는 것을 확인했다.
- 그리퍼 포함 MoveIt 설정을 만들었다.
- Gazebo를 띄우고 토픽 목록,타입과 관절상태를 보았다.
- 토픽으로 직접 관절 궤적을 발행하여 Gazebo에서 로봇이 목표자세로 움직이는 것을 확인하였다.
- Service를 이용해 controller manager의 controller 상태를 조회하여 joint_state_broadcaster와 rm_group_controller가 active 상태임을 확인하였다.

## 막힌 것/ 이해가 안 되는 것
-RViz와 Gazebo의 차이가 약간 헷갈렸다. RViz는 로봇상태와 각종 ROS 데이터를 시각화하는 프로그램으로 URDF의 로봇 모양, 센서 뎅터, MoveIt이 계산한 경로 등을 화면에 보여주지만 현실적인 물리계산을 하지않는다. 반면 Gazebo는 로봇이 실제환경에서 움직이는 것처럼 물리 시뮬레이션하는 프로그램으로 중력,충돌,물체 같은 물리 현상을 계산한다.

## 한 줄 소감
- RViz, MoveIt, Gazebo, controller가 각각 어떤 역할을 하고 ROS2에서 어떻게 연결되어 로봇을 움직이는지 직접 실습하며 전체적인 흐름을 이해할 수 있었다.
